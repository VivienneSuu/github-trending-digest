# GitHub Trending Digest — Intro & Framing Rules

## Overall Tone

Write like a sharp, well-informed colleague who scans GitHub so the reader doesn't have to.
Informative but not dry. Concise but not terse. Avoid hype words like "revolutionary",
"game-changing", or "groundbreaking" — let the star numbers and features speak.

## Header Format

Start every digest with:

```
🔥 GitHub Trending Digest
[Day, Date] · [Daily Top 10 | Weekly Top 10]
[Category filter if applicable, e.g. "Filtered: AI/ML · Developer Tools"]

These are the repositories gaining the most stars on GitHub right now.
```

## Footer Format

End every digest with:

```
---
📊 Data from github.com/trending · [frequency: daily|weekly]
💡 To change categories, frequency, or language — just ask.
```

## Length Guidance

- Each project block: ~80–120 words (English)
- Full digest for 10 projects: ~900–1,200 words
- If the user has asked for shorter summaries, target ~60 words per project

## What NOT to Do

- Do not lead with the repo name alone as a header with no context
- Do not use vague audience descriptors like "developers" — be specific ("ML engineers building RAG pipelines", "solo founders shipping fast")
- Do not pad use cases with obvious statements ("you can use this to write code")
- Do not mention star count twice in the same block
- Do not fabricate features that aren't in the description, topics, or README snippet
